Build rules

  1. One stylesheet. Edit tokens or shared component rules; never add DB-numbered patches.
  2. No !important. Fix the component or markup.
  3. No MutationObservers for layout. Render once from state and data.
  4. One component per job. KPI cards, tables, overlays, and controls are shared.
  5. Monospace is meaningful. Use it for references, times, docks, skids, and PO/BOL/job numbers.
  6. Customers see nothing internal. Mirror database isolation in the interface.
  7. Refresh never interrupts. Five-second polling pauses or patches safely during slot selection.
  8. Shadows only on overlays.
  9. Generate QR codes locally.
